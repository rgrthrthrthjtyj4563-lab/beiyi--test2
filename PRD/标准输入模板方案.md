# 标准输入模板方案

## 问题背景

传统的业务明细解析需要：
1. **智能匹配列名**：用户上传的列名和系统计费项名称可能不一致
2. **复杂的字段映射**：需要配置映射规则
3. **耗时较长**：50MB文件解析需要 10-30秒

## 解决方案：标准化输入模板

### 核心思路

**用"约定优于配置"替代"智能解析"，模板字段动态读取计费项配置**

```
传统方式                          标准模板方式
├─ 用户上传任意Excel               ├─ 下载标准模板
├─ 系统猜测列名含义                ├─ 按模板填写数据
├─ 模糊匹配字段                    ├─ 直接读取列名
├─ 耗时 10-30秒                    └─ 耗时 < 2秒
└─ 可能匹配错误
```

### 模板结构（与计费项配置对齐）

```excel
Sheet: 业务数据
┌────────┬────────┬────────────┬─────────────────┬─────────────────┬─────────┐
│  年份  │  月份  │ 服务提供方 │   租户基础服务费 │   医院拜访      │  ...... │
├────────┼────────┼────────────┼─────────────────┼─────────────────┼─────────┤
│  2024  │   1    │  示例服务商A │       1         │      100        │  ...... │
│  2024  │   2    │  示例服务商B │       1         │      120        │  ...... │
└────────┴────────┴────────────┴─────────────────┴─────────────────┴─────────┘

Sheet: 填写说明
┌──────────────────┬───────────────────────────┬────────┬────────┬────────┬───────────┐
│ 字段             │ 说明                      │ 层级   │ 单位   │ 单价   │ 计费模式  │
├──────────────────┼───────────────────────────┼────────┼────────┼────────┼───────────┤
│ 年份             │ 数据所属年份（必填）      │        │        │        │           │
│ 月份             │ 数据所属月份（必填）      │        │        │        │           │
│ 服务提供方       │ 服务商/供应方名称（必填）│        │        │        │           │

│ ......           │ ......                    │ ...... │ ...... │ ...... │ ......    │
└──────────────────┴───────────────────────────┴────────┴────────┴────────┴───────────┘
```

### 优势对比

| 维度 | 传统解析 | 标准模板 |
|------|---------|---------|
| **解析速度** | 10-30秒 | **< 2秒** |
| **准确性** | 依赖模糊匹配 | **100%准确** |
| **配置复杂度** | 需要字段映射 | **无需配置** |
| **大文件支持** | 容易超时 | **轻松支持** |
| **用户学习成本** | 低（任意格式） | 中（需学习模板） |
| **适用场景** | 已有数据文件 | **定期对账** |

## 使用流程

### 方式一：标准模板（推荐）

```
1. 下载标准模板
   ↓
2. 按模板格式填写业务数量
   ↓
3. 上传填写好的模板
   ↓
4. 系统秒级解析完成
```

### 方式二：兼容模式

```
1. 选择"兼容模式"
   ↓
2. 上传现有业务数据文件
   ↓
3. 系统自动匹配字段
   ↓
4. 等待解析完成（大文件需耐心等待）
```

### 解析逻辑对比

**传统解析（logic.py:parse_business_data_preview）**
```python
# 步骤复杂：
# 1. 读取所有列名
# 2. 和计费项名称模糊匹配
# 3. 应用字段映射规则
# 4. 账期筛选
# 5. 计算数量

for col in df.columns:
    mapped_name = fuzzy_match(col, valid_names)  # 模糊匹配
    if mapped_name:
        quantities[mapped_name] = df[col].sum()
```

**标准模板解析（template_parser.py:parse_standard_template）**
```python
# 步骤简化：
# 1. 直接读取计费项列
# 2. 计算数量

for item in config_items:
    if item.name in df.columns:
        quantities[item.name] = df[item.name].sum()
```

## 适用场景建议

### 推荐使用标准模板

- ✅ 定期为客户生成对账单（月度/季度）
- ✅ 客户愿意配合使用标准格式
- ✅ 数据量较大（>10MB）
- ✅ 对解析速度有要求

### 使用兼容模式

- ⚠️ 客户已有固定的业务系统导出格式
- ⚠️ 不愿改变现有工作流程
- ⚠️ 数据量较小（<1MB）
- ⚠️ 一次性对账

## 字段与校验规则（对齐计费项配置）

### 字段来源
- **系统字段**：`年份`、`月份`、`服务提供方`（固定）
- **业务字段**：来自**启用的计费项配置**（`load_config()`），按 L1→L4 + 择取优先级排序生成列

### 填写规则
- `年份`、`月份`、`服务提供方` 必填
- 计费项数量为非负数，允许为空（空值按 0 处理）
- 对应 `ACTUAL_FULL/ACTUAL_SELECTABLE` 的计费项建议填写实际数量
- `SIMULATED` 计费项可留空（系统可模拟填充）

### 校验规则（标准模板）
| 规则 | 校验逻辑 | 处理 |
|------|----------|------|
| 系统字段必填 | 必须存在 `年份`、`月份`、`服务提供方` 列 | 缺失判为无效模板 |
| 计费项字段匹配 | 至少包含 1 个启用计费项列 | 缺失提示 |
| 数值类型 | 非数字转为 0 | 继续解析 |
| 数量非负 | < 0 置 0 | 继续解析 |

## 总结

标准输入模板方案通过**约定优于配置**的思路，将复杂的智能解析简化为直接读取，带来：

1. **速度提升 10倍+**（30秒 → 2秒）
2. **准确率 100%**（无需模糊匹配）
3. **大文件友好**（支持 100MB+ 文件）
4. **向后兼容**（保留兼容模式）

这是从"工具适应数据"到"数据适应工具"的转变，虽然增加了用户的一点点学习成本，但显著提升了系统的可靠性和性能。
