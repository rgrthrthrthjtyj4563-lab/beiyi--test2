
产品需求文档（PRD）
医药合规对账单智能生成引擎 v1.0
文档版本
v1.0
撰写日期
2026-02-10
适用对象
医药合规SaaS计费团队、财务对账专员
核心目标
将大额开票金额自动拆解为可审计、可解释的细颗粒度计费清单
1. 产品目标
完全化解：输入金额必须被完全分配到各个计费项，总和精确到分（±0.00元）。
审计合规：每个计费项均需提供业务依据（实际数据或合理估算）及文字解释。
灵活适配：支持不同客户类型（大客户/小客户）自动调整分配策略。
二、核心功能逻辑：四层化解模型
2.1 分层架构定义
层级	定位	计费项示例	单价范围	目标占比
L1 系统收费层	高频业务行为计费	医院拜访、API调用、基础运维	30-3000元	50-60%
L2 报告辅助加工	人天增值服务	药事报告、竞品分析	3000元/人天	25-35%
L3 增值服务	知识付费	合规课程、知识库订阅	10-500元	10-15%
L4 其他服务	尾数调平	数据整理、快递代收	50-500元	0-5%
2.2 资金分配优先级（关键逻辑）
资金按以下固定顺序分配，前一层级填满后进入下一层：
1.P0 必须项：租户基础服务费（2000元/月）—— 只要有业务发生即收取。
2.P1 实际数据：用客户提供的实际业务数量计算金额（如拜访8992次×30元）。
3.P2 系统模拟：基于实际数据估算系统资源消耗（如API调用包数）。
4.P3 人天增值：剩余金额的80%优先填充高单价人天服务（3000元/人天）。
5.P4 小额增值：剩余小额分配给低单价课程（120元/节）。
6.P5 尾数调平：最后剩余的几元/几十元由L4吸收，确保总额匹配。
3. 功能范围
3.1 必做（MVP）
计费项管理：支持配置计费项名称、单位、单价、所属层级、是否允许模拟数量。
对账单生成：输入客户、账期、目标金额，自动生成草稿对账单。
自动分层分配：按L1~L4层级及优先级分配金额，确保总额与占比合规。
对账单详情：展示汇总金额、分层占比、明细行及可追溯数据来源。
导出功能：支持导出Excel（必须）和PDF（可选）格式对账单。
4. 核心概念（用“简单话”解释）
计费项：对账单上的一行收费内容，例如“医院拜访（次）”“报告处理（人天）”“课程订阅（套）”。
数量来源：每个计费项的数量来源，包括系统日志、业务记录、交付记录或人工补齐。
分层（L1~L4）：将费用分为四类，便于客户理解与复核：
oL1：系统使用产生的费用（偏软件使用）；
oL2：人工处理的报告/分析费用（偏交付）；
oL3：培训、订阅等附加服务费用（偏增值）；
oL4：其他支持性费用（用于补齐尾数）。
目标金额：本次对账单需达到的总额（通常等于开票金额）。
5. 业务规则（计算与分配）
5.1 总额规则
对账单总金额必须等于目标金额（如647,183.68元）。
允许使用L4做尾数调整，但占比不得超过配置上限（默认5%）。
5.2 分层占比规则
系统根据配置保证各层级占比范围：
L1：50%–60%
L2：25%–35%
L3：5%–10%（或10%–15%，由管理员选择默认模板）
L4：0%–5%
5.3 大额与小额的优先策略
大额优先：优先分配到“人天类”或“报告处理类”计费项（通常属于L2），便于解释为交付工作量。
小额优先：优先分配到L3（课程/订阅/内容包）补齐。
最后尾数：用L4的“其他服务”补齐到分角（如0.68元），并标记为“尾数调整”。
5.4 数量不足时的模拟规则
当某计费项本账期无可用数量来源但需生成对账单时：
该计费项必须被设置为“允许模拟”。
6. 详细功能需求
6.1 计费项管理（后台）
入口：系统设置 → 计费项管理
功能：新增/编辑/停用计费项
字段：
计费项名称
所属层级（L1/L2/L3/L4）
单位（次/份/条/人天/套…）
单价（含税/不含税可选）
数量来源类型：系统自动 / 人工录入 / 允许模拟
是否允许折扣（是/否）
是否需要审批（默认：人工录入与模拟需审批）
校验：
单价必须 ≥ 0
停用计费项不影响历史对账单
6.2 对账单生成（核心）
入口：对账单 → 新建对账单
输入：
客户公司
账期（年月/季度/自定义起止日期）
目标金额（如647,183.68元）
使用的分层比例模板（如“标准模板A”）
输出：生成“草稿对账单”，包含：
L1~L4金额与占比
对账单明细行（计费项、数量、单价、小计）
缺少数量的项目进入“待补齐”列表
生成逻辑：
1.系统先计算可从系统取到数量的计费项（形成基础账单）。
2.按比例范围计算每一层需补充的金额。
3.补齐顺序：先补L2（人天类、报告类）→ 再补L3（课程/订阅类）→ 最后补L4（尾数）。
生成后检查：
总额是否等于目标金额
各层占比是否在范围内
若失败，给出原因及调整建议
6.3 对账单详情页（可追溯）
入口：对账单 → 详情
页面模块：
顶部信息：客户、账期、目标金额、生成时间、状态（草稿/审批中/已确认/已导出）。
汇总区：L1~L4金额+占比（进度条显示是否在范围内）。
明细行表格：层级、计费项、数量、单价、小计、数量来源（系统/人工/模拟）、“查看依据”按钮（可查看对应明细列表）。
待补齐区：列出缺少数量的计费项，提示需补齐/模拟并提交审批。
操作区：提交审批、导出、生成说明、锁定账单。
查看依据：
系统来源：展示业务记录列表（可分页导出）。
报告类：展示报告清单、交付时间、负责人。
人工/模拟：展示填报人、时间、原因、审批记录。
6.4 模拟补齐与审批
触发：某计费项数量为0或无法获取，且允许模拟时。
流程：
1.系统给出建议数量（根据配置）。
2.运营填写/调整数量+必填原因。
3.提交审批。
4.审批通过后计入账单；拒绝则退回修改。
审批记录：需保留审批人、时间、意见、前后数量差异（用于审计）。
6.5 导出
支持格式：Excel（必做）、PDF（可选）。
Excel内容：
o汇总（L1~L4）
o明细行
o依据清单（可选：仅导出统计，不导出全量明细）
六、业务规则与约束
6.1 硬性规则（不可违反）
精度规则：生成金额总和必须精确等于开票金额，误差≤0.01元。
调平限制：L4层调平金额不得超过1,000元（超过则提示分配策略失衡）。
单价约束：同一收费项在全单中单价必须一致（不可部分30元、部分35元）。
6.2 弹性规则（场景适配）
占比浮动：目标占比仅作参考，若实际业务数据导致某层超占比（如L1占74%），允许接受现实。
优先级调整：客户明确要求“多分配至课程”时，可提升L3优先级。
模拟依据：API调用量、人天数等模拟数据需有业务逻辑支撑（如拜访次数×系数）。



6.3 异常处理规则
异常场景	处理逻辑
已知金额 > 开票金额	直接报错：业务数据已超支，需核对数据。
剩余金额 < 0	报错：输入数据矛盾。
L1占比 > 80%	预警提示：建议将部分拜访改为“协访”计入L2，或拆分至下月。
尾数差额 > 1,000元	告警：差额过大，建议增加L3课程数量或减少L2人天。
